# Telegram bot

## Запуск через Docker Compose

1. Создайте `.env` на основе `.env.example`.
2. Укажите `BOT_TOKEN` и ID администраторов в `ADMIN_IDS`.
3. Запустите бота:

   ```powershell
   docker compose up --build -d
   docker compose logs -f bot
   ```

Остановка: `docker compose down`. Данные SQLite, FSM-состояния, логи и резервные
копии хранятся в отдельных Docker volumes и переживают пересоздание контейнера.
Чтобы удалить в том числе данные, используйте `docker compose down -v`.

SQLite хранится в томе `bot_data`; отдельный контейнер базы данных не требуется.
FSM-данные хранятся в таблице `fsm_storage` той же SQLite-базы.
Запускайте только один экземпляр бота для этого SQLite-файла.

## Резервное копирование и восстановление

Бэкапы создаются автоматически перед изменением схемы. Перед ручным
восстановлением обязательно остановите бота, чтобы исключить активные соединения:

```powershell
docker compose stop bot
docker compose run --rm bot python restore.py /app/backups/<имя_файла>.db
docker compose start bot
```

Для локального запуска остановите `main.py` и выполните
`python restore.py <путь_к_резервной_копии.db>`. Скрипт проверяет SQLite,
внешние ключи и схему, подготавливает восстановленную базу отдельно и только
затем заменяет рабочий файл. Текущая база сохраняется в `backups/` для отката.
Повреждённые или несовместимые копии не устанавливаются.

Схема SQLite имеет версию `12` в `PRAGMA user_version`; приложение проверяет
и применяет обновление схемы при запуске.

## Локальный запуск

Создайте и заполните `.env`, установите зависимости из `requirements.txt`, затем:

```powershell
python main.py
```

Для запуска конфигурация требует `BOT_TOKEN` и `ADMIN_IDS`. ID администраторов
указываются через запятую. `LOG_LEVEL` поддерживает `DEBUG`, `INFO`, `WARNING`,
`ERROR` и `CRITICAL`. FSM-обновления одного пользователя сериализуются в одном
процессе; несколько экземпляров бота с общей SQLite-базой не поддерживаются.
